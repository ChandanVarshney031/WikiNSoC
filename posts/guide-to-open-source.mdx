# A Complete Guide to Open Source Contributions

Contributing to open source can be intimidating, but it is one of the most rewarding things you can do for your career and the community. This guide will walk you through the process of making your first meaningful contribution.

## Finding the Right Project

Don't just look for "good first issues" on random repositories. Instead, look at the tools you use every day. 

- Which libraries are in your `package.json`?
- Which frameworks do you love?
- Have you found a bug or a gap in the documentation?

Start there.

## The Contribution Workflow

1. **Fork the Repository**: Create your own copy of the project.
2. **Clone Locally**: `git clone https://github.com/your-username/repo.git`
3. **Create a Branch**: `git checkout -b fix/typo-in-docs`
4. **Make Changes**: Fix the issue or add the feature.
5. **Commit**: Write a clear, descriptive commit message.
6. **Push**: `git push origin fix/typo-in-docs`
7. **Open a Pull Request**: Explain exactly what you changed and why.

### Git Commands Quick Reference (Table)

| Stage | Action | Git Command | Recommended Flags |
| :--- | :--- | :--- | :--- |
| **Branch** | Create feature branch | `git checkout -b feature/xyz` | `-b` (creates & switches) |
| **Staging** | Stage modified files | `git add .` | `-p` (interactive staging) |
| **Commit** | Create git commit | `git commit -m "docs: update wiki"` | `-s` (sign-off) |
| **Push** | Push to remote fork | `git push -u origin feature/xyz` | `-u` (set upstream) |
| **Rebase** | Sync with main | `git pull --rebase upstream main` | `--autostash` |

### Pre-PR Checklist (Task Lists)

- [x] Read repository `CONTRIBUTING.md` guidelines
- [x] Code adheres to repository linting & formatting standards
- [x] Tested changes locally without errors
- [ ] Added documentation or wiki updates for new changes
- [ ] Linked PR to relevant GitHub Issue (e.g. `Fixes #42`)

> [!TIP]
> Always create a dedicated branch for every PR rather than committing directly to `main`. This allows you to work on multiple contributions in parallel without branch conflicts!

> [!NOTE]
> Keyboard shortcut: You can open GitHub's web editor on any repository by simply pressing <kbd>.</kbd> on your keyboard while viewing the repository page.

> [!WARNING]
> Never include secrets, API tokens, or `.env` files in your git commits. Always verify your `git status` before committing.

#### What happens if there are merge conflicts?
Simply rebase your branch on top of upstream main:
```bash
git fetch upstream
git rebase upstream/main
```
Resolve any conflict markers in your editor, then run `git rebase --continue`.
</details>

## Handling Feedback

Maintainers will often request changes. Don't take it personally! They are just trying to ensure the code meets their project's standards. Address the feedback politely, push the updates, and soon enough, your PR will be merged.

Welcome to the open-source community!
